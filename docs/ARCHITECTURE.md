# System Architecture Specification

## 1. Architectural Layers

HealthRisk AI follows Clean Architecture and SOLID design principles, dividing functionality into four decoupled layers:

### Presentation Layer (Frontend)
- **Framework**: React 18 with TypeScript and Vite.
- **Routing**: Client-side routing with `react-router-dom` v6.
- **State & Data**: Lightweight state with `zustand` (persisted authentication) and `tanstack-query` for automatic cache invalidation and query deduplication.
- **Visualization**: Modular SVG charts via `recharts` (BiomarkerTrendChart, RiskGauge).

### API & Orchestration Layer (Backend)
- **Framework**: FastAPI (async request handling).
- **Dependency Injection**: Database session scoping (`get_db`) and role-based token authentication (`get_current_active_user`).
- **Structured Logging**: `structlog` formatting events into structured JSON in production and readable logs in debug mode.

### Domain & Analytical Layer (Engines)
- **Document Processing**: `pdfplumber` for structured PDF table extraction, `PyPDF2` as fallback, `pytesseract` and `easyocr` behind the `OCRProvider` interface.
- **Clinical Normalization**: Alias lookup maps in `normalization_map.yaml` with biological plausibility filtering.
- **Engine 1 (Baseline)**: Z-score longitudinal variance analysis with zero-division safety and insufficient-data protection.
- **Engine 2 (Consistency)**: Configurable biological rules evaluating pairwise analyte constraints.
- **Engine 3 (Multi-Test Risk)**: Weighted risk scoring across multiple organ panel categories.

### Persistence Layer (Database)
- **RDBMS**: PostgreSQL 15.
- **ORM**: SQLAlchemy 2.0 Async (`asyncpg`).
- **Migrations**: Alembic with autogenerated version scripts.
- **Identities**: UUIDv4 across all primary keys.

## 2. Document Processing Pipeline

```
Raw Document (PDF/Image)
          │
          ▼
File Validation (Type check, size check < 20MB)
          │
          ▼
Text Stream Detection
  ├─> Native text stream present? ──> Extract text & tables via pdfplumber
  └─> Scanned / Flat Image? ────────> OCR routing (Tesseract primary, EasyOCR fallback)
          │
          ▼
Clinical NLP Parsing
  ├─> Table row regex parser (name, value, unit, reference interval, abnormal flag)
  ├─> Unstructured line pattern matcher
  └─> spaCy biomedical / linguistic tokenization
          │
          ▼
Biomarker Normalization
  ├─> Lookup alias against canonical catalog (normalization_map.yaml)
  ├─> Biological plausibility boundaries check
  └─> Unit standardization (unit_converter.py)
          │
          ▼
Confidence Scoring
  └─> Weighted synthesis of numeric detection, unit matching, reference range,
      canonical recognition, plausibility, and OCR clarity
          │
          ▼
Interactive Clinician Review Table (Flagging if confidence < 0.65)
```

## 3. Mathematical Specifications

### Baseline Z-Score Formula
$$\mu = \frac{1}{n} \sum_{i=1}^n X_i$$
$$\sigma = \sqrt{\frac{1}{n} \sum_{i=1}^n (X_i - \mu)^2}$$
$$Z = \begin{cases} \frac{X_{\text{current}} - \mu}{\sigma} & \text{if } \sigma > 0 \\ \text{None} & \text{if } \sigma = 0 \end{cases}$$

### Biological Consistency Score Formula
$$\text{Consistency Score} = 1 - \frac{\sum_{k \in \text{Violations}} W_k}{\sum_{k \in \text{Evaluated}} W_k}$$

### Multi-Test Risk Score Formula
$$\text{Risk Score}_{c} = \sum_{j \in \text{Features}_c} (f_j \cdot w_j)$$
$$\text{Normalized Risk}_c = \frac{\text{Risk Score}_c}{\sum_{j} w_j}$$
$$\text{HRI} = \frac{\sum_c (\text{Normalized Risk}_c \cdot \text{Severity Weight}_c)}{\sum_c \text{Severity Weight}_c}$$
